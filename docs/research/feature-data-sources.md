# Environmental feature data sources (verified 2026-10-02)

This note records completed official-source checks from the AquaWatch feature research workflow. Forecast/model values are not ground observations or official safety warnings unless explicitly stated.

## Earthquakes and tsunami information

- **USGS earthquake GeoJSON feeds:** `https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php` and feed detail `https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_day.geojson`. Public, no-key GeoJSON feeds; near-real-time feed updates every minute. Records include magnitude, origin time, hypocenter coordinates/depth, and a `tsunami` metadata value. The tsunami flag is not itself a forecast, coastal inundation polygon, or replacement for NOAA warning products. Use magnitude/time/depth as event details; avoid claiming a measured shockwave radius.
- **Official tsunami advisories:** NOAA Tsunami Warning Centers publish Atom/CAP product feeds and authoritative alert pages; use their posted alert polygons/status as the source of record. The research established official feed/documentation discovery but did not verify a stable consumer JSON API for arbitrary advisory polygons. Do not infer active alerts from earthquake metadata.
- Sources: [USGS feeds](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php), [USGS GeoJSON detail](https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_day.geojson), [NOAA Tsunami Warning Centers](https://www.tsunami.gov/).

## Sentinel-5P atmospheric composition

- Copernicus Data Space Ecosystem OData provides Sentinel-5P Level-2 products with OAuth bearer-token access; public account registration/terms apply. It is not an anonymous no-key point API. Credentials/tokens belong on the server, not in client JavaScript.
- Relevant Level-2 products include NO2, SO2, and aerosol index. Values are satellite column products (e.g. NO2 in mol/m²), not surface PM2.5/PM10 or a consumer AQI. Apply the product's quality flag/QA threshold and surface the overpass/acquisition time; the product is a swath and has cloud/coverage gaps. Product latency depends on processing stream; the checked docs describe NRT target processing around three hours, not a guaranteed application-level delivery time.
- Do not present satellite column concentrations as ground-level exposure, nor describe the Sentinel-5P layer as a PM2.5 map. Existing Open-Meteo modeled air-quality values remain a separate product and require correct model/source/attribution disclosure.
- Sources: [Copernicus Data Space documentation](https://documentation.dataspace.copernicus.eu/), [Sentinel-5P data access](https://dataspace.copernicus.eu/explore-data/data-collections/sentinel-data/sentinel-5p), [Copernicus Sentinel-5P products](https://sentinels.copernicus.eu/web/sentinel/missions/sentinel-5p).

## NOAA OISST and climate context

- NOAA NCEI daily Optimum Interpolation SST (OISST) is a global 0.25-degree gridded product with a record beginning in 1981. The daily blended analysis is delayed relative to the calendar day; display the actual source date from returned metadata rather than claiming real-time observation. It includes SST and anomaly fields, with the product's own climatological reference period/metadata. It is an analysis product, not a live buoy observation.
- NOAA CPC's Relative Oceanic Niño Index (RONI) / ENSO index is monthly climate context, not a global ocean heat map. Use it only with the exact NOAA-reported month and value; clearly separate it from spatial SST anomaly data.
- Sources: [NCEI Daily OISST](https://www.ncei.noaa.gov/products/optimum-interpolation-sst), [NCEI ERDDAP OISST v2.1](https://www.ncei.noaa.gov/erddap/griddap/), [NOAA CPC ENSO indices](https://www.cpc.ncep.noaa.gov/data/indices/).

## Waves and ocean currents

- **Open-Meteo Marine API:** `https://marine-api.open-meteo.com/v1/marine?latitude={lat}&longitude={lon}&hourly=wave_height,wave_direction,swell_wave_height,swell_wave_direction,ocean_current_velocity,ocean_current_direction,wave_period`. The official API docs list hourly wave/swell heights (m), wave/swell directions (degrees; wave bearings indicate where waves come from), wave periods (s), current velocity (default km/h; units selectable), current direction (direction the water flows toward), and sea-surface temperature.
- Global model grids are typically several to tens of kilometres; the documented global current/tide grid is about 0.08 degrees. The response is hourly model output, not hourly direct observation; source model refresh intervals differ. Endpoint forecast horizon is at most 8 days. Accuracy is limited near coasts; these values are unsuitable as sole basis for navigation, rescue, or safety decisions. It does not provide official marine advisories.
- The Marine endpoint documents `sea_surface_temperature`, but it is not used as a substitute for the separately labelled NOAA OISST daily analysis or its long-term anomaly field.
- Open-Meteo free tier has no key for non-commercial use, with published request caps (600/min, 5,000/hour, 10,000/day, 300,000/month) and no uptime guarantee. Commercial use needs the paid/customer API. Provide visible Open-Meteo attribution/link and comply with CC BY 4.0; disclose model nature, timestamps, units, missing values, and location privacy. Copernicus source-product data require their own attribution/licence terms if accessed directly.
- Sources: [Open-Meteo Marine API](https://open-meteo.com/en/docs/marine-weather-api), [Open-Meteo pricing/access](https://open-meteo.com/en/pricing), [Copernicus global wave product](https://data.marine.copernicus.eu/product/GLOBAL_ANALYSISFORECAST_WAV_001_027/description), [Copernicus global physics product](https://data.marine.copernicus.eu/product/GLOBAL_ANALYSISFORECAST_PHY_001_024/description), [Copernicus Marine licence](https://marine.copernicus.eu/user-corner/service-commitments-and-licence).

## Global marine map rendering

- The ocean page requests hourly model values for 56 fixed ocean sample locations with `cell_selection=sea` and a seven-day forecast horizon. Wave-height, swell-height, and current-speed heatmaps are display interpolations between those returned model samples; the interpolation fills a visual surface but is not a provider-native NOAA wave raster or a new independent measurement. Flow bearings use Open-Meteo's documented semantics: ocean currents point toward their direction, while wave/swell bearings point from the direction the waves arrive.
- For the ocean-only mask and the SST/SST-anomaly image layer, the backend queries the tested NOAA NCEI preliminary near-real-time ERDDAP dataset `ncdcOisst21NrtAgg_LonPM180` (`sst` or `anom`) at its global daily 0.25° grid and returns a transparent PNG reprojected to Web Mercator for Leaflet. The live `.das` endpoint reports `time_coverage_end`; at validation on 2026-10-03 its latest field was 2026-10-01. NOAA describes the preliminary stream as roughly one-day latency and replacement with a final analysis after about two weeks; display the actual source time and do not call it instant or forecast data. The dataset's longitude centres run from -179.875° to +179.875°. NOAA anomalies use the product's 1971–2000 reference. The renderer caches each metric for six hours. The NCEI product page remains the authoritative description; the former NCEI ERDDAP URL's `.das` endpoint returned 404 during validation, so the application uses the live CoastWatch mirror.
- Official documentation and endpoint checks: [NOAA NCEI OISST product page](https://www.ncei.noaa.gov/products/optimum-interpolation-sst), [NCEI final-analysis ERDDAP form](https://www.ncei.noaa.gov/erddap/griddap/ncdc_oisst_v2_avhrr_by_time_zlev_lat_lon.html), [verified NOAA CoastWatch NRT ERDDAP form](https://coastwatch.pfeg.noaa.gov/erddap/griddap/ncdcOisst21NrtAgg_LonPM180.html), [Open-Meteo Marine API variables and forecast limits](https://open-meteo.com/en/docs/marine-weather-api), and [NOAA Global Ensemble Ocean Wave Forecast System](https://polar.ncep.noaa.gov/waves/ensemble/). NOAA documents its Global Ensemble WAVEWATCH III forecast on a 0.25° grid with four cycles per day and up to 16 days, but that gridded feed is not the wave field used by the current browser interpolation.

## Integration rules

1. Keep values paired with source, model/product name, timestamp, units, and relevant coverage limitations.
2. Never label modeled or gridded analysis data as local measured readings.
3. Never infer safety alerts, tsunami zones, or navigation guidance from generic event or model fields.
4. Do not embed user-supplied API credentials in front-end code; secrets remain in backend environment configuration.
5. Do not claim a data layer is operational until it has passed an endpoint smoke test and the UI displays provider timestamps / empty-state behavior.


## Historical U.S. radar/event archives

- NOAA/NCEI NEXRAD Level-II raw radar volumes are public and can be retrieved from AWS `unidata-nexrad-level2` in `us-east-1`; the former `noaa-nexrad-level2` bucket was deprecated in 2025. Level-II is compressed native radar volume data, not pre-rendered map tiles or JSON. A production replay needs backend station/time discovery, selective object download, a decoder such as Py-ART or Weather and Climate Toolkit, caching, and map-ready tile/frame generation. Coverage is the U.S. network, not global. Scans recur roughly every 4.5–10 minutes; archive availability is approximately a day behind, and station history/coverage varies.
- NOAA NCEI Storm Events CSV/Parquet is retrospective event-report data (1950 onward) with details, locations, and fatalities files linked by event ID. Bulk publication is about 75 days after month-end. These reports are not instantaneous sensor observations or current alerts.
- NASA EONET remains the lightweight, global, browser-usable event feed for recent events. Its dated point geometry can support an educational position replay when multiple positions exist. This does not supply event pressure/rainfall fields and should not be presented as a 30-year storm archive. The current implementation therefore replays only source-provided point sequences and links to NOAA for deeper radar/archive analysis.
- Sources: [NCEI NEXRAD](https://www.ncei.noaa.gov/products/radar/next-generation-weather-radar), [NEXRAD AWS registry](https://registry.opendata.aws/noaa-nexrad/), [NEXRAD Level-II ICD](https://www.roc.noaa.gov/public-documents/icds/2620002N.pdf), [NCEI Storm Events bulk data](https://www.ncei.noaa.gov/access/storm-events-database/bulk-data), [NASA EONET API documentation](https://eonet.gsfc.nasa.gov/docs/v3).


## NASA FIRMS fires and smoke context

The global FIRMS Area API uses `https://firms.modaps.eosdis.nasa.gov/api/area/csv/{MAP_KEY}/{SOURCE}/{AREA_COORDINATES}/{DAY_RANGE}`. It accepts `world` or a bounding box and a 1–5 day request window. Supported NRT sources include `VIIRS_NOAA20_NRT`, `VIIRS_NOAA21_NRT`, `VIIRS_SNPP_NRT`, and `MODIS_NRT`; request a free MAP_KEY and keep it server-side. NASA documents a limit of 5,000 transactions per 10 minutes. Global NRT products are generally available within about three hours of satellite observation; VIIRS nominal pixel size is about 375 m, but acquisitions are at satellite overpass times. NOAA-20/21 are preferred for continuity: NASA notes Suomi-NPP delivery is scheduled to cease November 1, 2026. CSV includes lat/lon, acquisition date/time (UTC), sensor/satellite, confidence, fire radiative power (MW), and sensor-dependent brightness temperatures (K). Pixels are hot-surface detections—not fire perimeters, proof of vegetation fire, smoke forecasts, or confirmed ground incidents. FIRMS smoke context is corrected-reflectance imagery and OMPS Aerosol Index, not a verified structured smoke-vector feed. Sources: [FIRMS Area API](https://firms.modaps.eosdis.nasa.gov/api/area/), [FIRMS map WMS](https://firms.modaps.eosdis.nasa.gov/mapserver/wms-info/), [FIRMS fire attributes](https://www.earthdata.nasa.gov/data/tools/firms/active-fire-data-attributes-modis-viirs), [NASA smoke imagery guidance](https://www.earthdata.nasa.gov/news/blog/viewing-smoke-firms), [FIRMS FAQ](https://www.earthdata.nasa.gov/data/tools/firms/faq).

## Official tsunami products

USGS real-time GeoJSON feeds offer recent earthquake catalog events and metadata; their feeds are refreshed each minute, but event solutions may be revised. A USGS `tsunami` property is not a tsunami alert; USGS does not issue tsunami warnings. NOAA Warning Centers provide official products as Atom/CAP feeds: NTWC [Atom](https://www.tsunami.gov/events/xml/PAAQAtom.xml), [CAP](https://www.tsunami.gov/events/xml/PAAQCAP.xml); PTWC [Atom](https://www.tsunami.gov/events/xml/PHEBAtom.xml), [CAP](https://www.tsunami.gov/events/xml/PHEBCAP.xml). CAP-TSU includes issuer, issue time, status/type, urgency/severity/certainty, headline/description and product areas; optional local predicted/observed arrival and wave-height values can be included and are not always present. Validate signatures for raw CAP when relying on it. NOAA does not publish a fixed refresh/latency guarantee for these feeds in the reviewed docs; distinguish model predictions from observations and link the official bulletin. Sources: [USGS FDSN event API](https://earthquake.usgs.gov/fdsnws/event/1/), [USGS feeds](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php), [NOAA product retrieval](https://www.tsunami.gov/?page=productRetrieval), [NOAA CAP profile](https://www.tsunami.gov/?page=cap), [U.S. Tsunami Warning System](https://www.noaa.gov/explainers/us-tsunami-warning-system).

## Copernicus Sentinel-5P

CDSE catalog OData is `https://catalogue.dataspace.copernicus.eu/odata/v1/Products`; Sentinel-5P Level-2 NO2 product type is `L2__NO2___`, and a selected product downloads as NetCDF from `https://download.dataspace.copernicus.eu/odata/v1/Products({product_id})/$value`. Download requires a CDSE account and bearer token through the documented identity/OAuth flow (`client_id=cdse-public` with username/password to obtain the token). Data are free/full/open subject to account quotas/fair use; secrets/tokens must remain server-side. NO2 values such as tropospheric/total column are in mol/m², with `qa_value` (0–1) and geolocation/time fields; filter using the product manual (typically retain `qa_value >= 0.75`). Products are daily swath observations with cloud/coverage gaps, not ground-level PM/AQI or continuous pollution measurements. The Level-2 collection is world-extent from April 2018; ESA's NRT processing target is within about three hours, not an end-to-end guarantee. Sources: [CDSE Sentinel-5P collection](https://dataspace.copernicus.eu/data-collections/copernicus-sentinel-missions/sentinel-5p), [CDSE OData API](https://documentation.dataspace.copernicus.eu/APIs/OData.html), [NO2 product manual](https://sentiwiki.copernicus.eu/__attachments/a_9a684b9fae014dbd44f68f924be68b04ef2a8740ab3a4a756a2b18393c06a80b/S5P-KNMI-L2-0021-MA%20-%20Sentinel-5P%20Level%202%20Product%20User%20Manual%20Nitrogendioxide%202025-4.5.0.pdf), [ESA data products](https://www.esa.int/Applications/Observing_the_Earth/Copernicus/Sentinel-5P/Data_products), [CDSE terms](https://dataspace.copernicus.eu/terms-and-conditions).

## NOAA OISST and ENSO index

NOAA NCEI OISST v2.1 is the daily global 0.25° product, with SST (`sst`, °C), anomaly (`anom`, °C relative to the 1971–2000 OI.v2 climatology), error (`err`) and ice (`ice`) fields. The application uses NOAA's preliminary near-real-time CoastWatch ERDDAP mirror, `ncdcOisst21NrtAgg_LonPM180`, with `time`, `zlev`, latitude and signed-longitude dimensions; `sst`/`anom` point and global raster queries were live-tested on 2026-10-03. NOAA describes the preliminary stream as typically about one day behind and replaced by the final product after roughly two weeks. Query `time_coverage_end` and surface the returned date, since service access or production may lag; the former NCEI ERDDAP `.das` URL returned 404 in the live check. The NRT dataset's longitude centres span -179.875° to +179.875°; snap coordinates to exact cell centres. NOAA CPC RONI is a separate monthly derived index: [RONI ASCII](https://www.cpc.ncep.noaa.gov/data/indices/RONI.ascii.txt), columns `SEAS`, `YR`, `ANOM`; it is based on ERSSTv6 Niño 3.4 minus tropical-mean SST anomalies and is not a spatial SST map or a forecast. Recent RONI can be revised for up to two months. Sources: [NCEI OISST overview](https://www.ncei.noaa.gov/products/optimum-interpolation-sst), [NCEI final ERDDAP form](https://www.ncei.noaa.gov/erddap/griddap/ncdc_oisst_v2_avhrr_by_time_zlev_lat_lon.html), [NOAA CoastWatch NRT ERDDAP form](https://coastwatch.pfeg.noaa.gov/erddap/griddap/ncdcOisst21NrtAgg_LonPM180.html), [NOAA CPC RONI](https://www.cpc.ncep.noaa.gov/products/analysis_monitoring/enso/roni/), [NOAA RONI change notice](https://www.weather.gov/media/notification/pdf_2026/pns26-05_Relative_ONI.pdf).

## Community observations and public water data

No verified public write API exists for arbitrary users to post fresh geotagged observations; AquaWatch's current user pins are first-party browser-local records and are not shared or verified. EPA/USGS/NWQMC Water Quality Portal is a public, read-only dataset (`https://waterqualitydata.us/wqx3/Station/search` and `/Result/search`) of contributor measurements; preserve the contributing provider, sample date, result value and reported unit because records are discrete samples with contributor-dependent delay, not live community reports. CrowdHydrology provides volunteer staff-gauge stage readings at participating stations but no verified general posting API, and its current public station list/status is uncertain. Consent before device location or public reports; allow manual/coarse placement and avoid exposing identities. Sources: [CrowdHydrology](https://crowdhydrology.geology.buffalo.edu/), [University at Buffalo overview](https://www.buffalo.edu/news/releases/2013/06/025.html), [Water Quality Portal WQX API](https://www.waterqualitydata.us/beta/webservices_documentation/), [WQP user guide](https://www.waterqualitydata.us/portal_userguide/), [EPA data download guide](https://www.epa.gov/waterdata/water-quality-data-download).

## GIS and cinematic tools source limits

No reviewed source natively supplies one bounding-box download simultaneously as GeoJSON, GeoTIFF and NetCDF. NOAA ERDDAP griddap provides constrained raster subsets in NetCDF; tabledap can return GeoJSON for actual tabular point datasets, but does not turn a raster grid into point measurements. Copernicus Marine subset products write gridded NetCDF (and supported alternatives), not GeoJSON output. Example verified NOAA raster: NOAA-20 VIIRS weekly chlorophyll (`nesdisVHNnoaa20chlaWeekly_Lon0360`) is an experimental remote-sensing estimate; research-time actual coverage was 2021-08-21 to 2026-09-14, despite a longer nominal product title. Do not relabel its imagery or values as in-situ water-quality measurements. Sources: [ERDDAP griddap docs](https://www.ncei.noaa.gov/erddap/griddap/documentation.html), [ERDDAP tabledap docs](https://www.ncei.noaa.gov/erddap/tabledap/documentation.html), [NOAA chlorophyll dataset](https://coastwatch.pfeg.noaa.gov/erddap/griddap/nesdisVHNnoaa20chlaWeekly_Lon0360.html), [Copernicus subset API](https://help.marine.copernicus.eu/en/articles/8283072-copernicus-marine-toolbox-api-subset), [Copernicus account/data access](https://help.marine.copernicus.eu/en/articles/4220332-how-to-sign-up-for-copernicus-marine-service).

For globe lighting context, USNO's documented one-day JSON service is location/date-specific and is not a global real-time vector service: `https://aa.usno.navy.mil/api/rstt/oneday?date=YYYY-MM-DD&coords=LAT,LON&tz=OFFSET`; local astronomical calculations are suitable for globe shading when clearly labeled as calculations. NASA GIBS WMTS offers global processed imagery (`https://gibs.earthdata.nasa.gov/wmts/epsg4326/best/`) with product-specific dates/latency; NDBC buoy products (`https://www.ndbc.noaa.gov/data/realtime2/{station}.txt`) are sparse station observations, not a dense global field. Browser-based camera recording is device/browser dependent and records the rendered canvas, not a deterministic high-res render. Sources: [USNO API](https://aa.usno.navy.mil/data/api), [NASA GIBS API](https://www.earthdata.nasa.gov/engage/open-data-services-software/earthdata-developer-portal/gibs-api), [NDBC observation descriptions](https://www.ndbc.noaa.gov/obsdes.shtml), [MediaRecorder API](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder).
